# Публикация университетских конспектов

Сайт: https://graymans1on.github.io/university-notes/

Исходные конспекты и данные находятся в `content/`, оформление и карта — в `assets/`, сборка и проверки — в `scripts/`.

GitHub Actions автоматически собирает и публикует изменения ветки `main`. В Settings → Pages источником должен быть GitHub Actions.

Локальная проверка из корня репозитория:

```sh
npm ci
node scripts/build-notes.mjs
python3 scripts/validate-site.py
python3 scripts/export-pages.py
```

`dist/` содержит обычную сборку. `pages-output/` содержит версию с путями `/university-notes/` для GitHub Pages. Обе папки создаются автоматически и не хранятся в репозитории. Выгрузки Markdown также ссылаются на новый адрес.

Методы оформления и проверки конспектов описаны в MAINTENANCE.md. Для этого репозитория публикация через GitHub Actions заменяет описанный там выпуск через Sites. Прежний сайт оставлен доступным отдельно.

## Android и разовые изменения

Расписание собирается из постоянного цикла `content/schedule.json` и дополняемого журнала `content/schedule-exceptions.json`. Реальные изменения не добавляются без исходных указаний. Схема и правила находятся в MAINTENANCE.md.

Публикация проверяет сайт, мобильный интерфейс, Java-тесты и Android lint, затем выдаёт APK как артефакт Actions. Если исходные секреты подписи заданы, публикует `android-v<версия>` в Releases и `/android/app-release.json` с `/android/app.apk` на Pages. Без ключа публичный feed APK не создаётся; артефакт помечен как неподписанный.

По текущему решению владельца админка работает с простым кодом на устройстве и собственным GitHub-токеном для записи. Отдельный сервер не используется. Решение и архив прежнего проекта находятся в `docs/ADMIN_ARCHITECTURE.md`.


Правки сайта и мобильного веб-интерфейса публикуют только обновление содержимого, без нового APK. Нативная сборка включается при изменении Android Java/XML/Gradle или упаковщика подписи, а также при ручном запуске workflow. Существующий публичный APK-feed при обновлении материалов восстанавливается из последнего подписанного GitHub Release.


## Текущий режим администратора

По новому требованию владельца отдельный сервер не используется. Код открывает интерфейс устройства; для публикации правок требуется GitHub-токен с правом Contents: Read and write только для этого репозитория. Постоянные и разовые изменения хранятся компактно и раздельно, без перезаписи исходного расписания. Актуальная схема — в `docs/ADMIN_ARCHITECTURE.md`; прежний серверный проект там сохранён как архив.

## Публикация учебников

На `/textbooks/` опубликованы четыре присланных PDF. Файлы доступны по HTTPS из `/books/`; рядом с каждой книгой есть онлайн-ссылка и отдельное сохранение офлайн. Для сайта используется CacheStorage и `textbooks-sw.js`, для Android — существующее файловое хранилище и PDF-просмотрщик.

Оригинальные байты хранятся частями в `books/source/`, контрольные суммы — в `books/sources.json`. После экспорта сайта и подготовки Android feed выполните `python3 scripts/prepare-textbooks.py`. Команда проверяет части и собирает полные PDF только в `pages-output/books/`. Не копируйте PDF в dist, APK или Android feed. Каталог и интерфейс доставляются штатным обновлением материалов без нового APK.
