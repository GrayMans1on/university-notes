# Публикация университетских конспектов

Сайт: https://graymans1on.github.io/university-notes/

Исходные конспекты и данные находятся в `content/`, оформление и карта — в `assets/`, сборка и проверки — в `scripts/`.

GitHub Actions автоматически собирает и публикует изменения ветки `main`. В Settings → Pages источником должен быть GitHub Actions.

Локальная проверка из корня репозитория:

```sh
npm ci
node scripts/build-notes.mjs
python3 scripts/validate-site.py
python3 scripts/export-pages.py
```

`dist/` содержит обычную сборку. `pages-output/` содержит версию с путями `/university-notes/` для GitHub Pages. Обе папки создаются автоматически и не хранятся в репозитории. Выгрузки Markdown также ссылаются на новый адрес.

Методы оформления и проверки конспектов описаны в MAINTENANCE.md. Для этого репозитория публикация через GitHub Actions заменяет описанный там выпуск через Sites. Прежний сайт оставлен доступным отдельно.

## Android и разовые изменения

Расписание собирается из постоянного цикла `content/schedule.json` и дополняемого журнала `content/schedule-exceptions.json`. Реальные изменения не добавляются без исходных указаний. Схема и правила находятся в MAINTENANCE.md.

Публикация проверяет сайт, мобильный интерфейс, Java-тесты и Android lint, затем выдаёт APK как артефакт Actions. Если исходные секреты подписи заданы, публикует `android-v1.0.2` в Releases и `/android/app-release.json` с `/android/app.apk` на Pages. Без ключа публичный feed APK не создаётся; артефакт помечен как неподписанный.

Безопасная админка требует отдельного сервера. Документ для согласования — `docs/ADMIN_ARCHITECTURE.md`; сервер не подключён.


Правки сайта и мобильного веб-интерфейса публикуют только обновление содержимого, без нового APK. Нативная сборка включается при изменении Android Java/XML/Gradle или упаковщика подписи, а также при ручном запуске workflow. Существующий публичный APK-feed при обновлении материалов восстанавливается из последнего подписанного GitHub Release.
