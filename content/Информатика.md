## Системы счисления

### Перевод двоичных чисел в шестнадцатеричные

Двоичное число разбивают на группы по четыре бита справа налево. Каждая группа соответствует одной шестнадцатеричной цифре.

Веса битов в группе: $8,4,2,1$.

Веса разрядов двоичной системы — степени двойки.

:::example Число 1100 1110 0110₂ и его шестнадцатеричная запись

$$
1100\,1110\,0110_2=CE6_{16}.
$$

Каждая группа из четырёх битов соответствует одной шестнадцатеричной цифре: $C$, $E$, $6$.

$$
1100_2=C_{16}.
$$

Веса битов в группе: $8,4,2,1$.

Веса разрядов двоичной системы — степени двойки.

## Алгоритмы и блок-схемы

### Вычисление факториала

Алгоритм вычисления $n!$ для неотрицательного целого $n$:
1. Начало.
2. Ввод $n$, начальное значение $Q=1$.
3. Проверка $n\ge1$.
4. Если условие выполнено: $Q=Q\cdot n$, $n=n-1$, затем возврат к проверке.
5. Если условие не выполнено: результат $Q$ равен $n!$; конец.


![Блок-схема с вводом, условием n≥1, ветвями Да/Нет, умножением, уменьшением n и возвратом к проверке.](/assets/factorial-flowchart.svg)

### Объединение цифр двух чисел

В обеих схемах цифры извлекаются **справа налево**. Для целого неотрицательного числа:

- `a % 10` — последняя цифра;
- `a // 10` — число без последней цифры;
- `n = 10*n + x` — приписать цифру `x` справа к результату;
- `n = n + x*L`, затем `L = 10*L` — поместить следующую цифру в разряд с весом `L`.

Входные числа в примерах: $a=13$, $b=229$. Их цифры расположены по возрастанию слева направо. Сравнивая последние цифры, каждый раз выбираем большую; при равенстве берём цифру из `b`. От выбранного числа отсекаем последнюю цифру.

**Для произвольных входных чисел это объединение в порядке выбора, а не сортировка всех цифр.** Числовое накопление не сохраняет ведущие нули результата. Упорядоченный результат получается при указанном порядке цифр в обоих исходных числах.

:::example Объединение цифр: приписывание справа

**Задача.** Объединить цифры чисел 13 и 229, каждый раз выбирая большую из доступных последних цифр и приписывая её справа к результату.

Начальное значение `n = 0`. Продолжаем, пока `a > 0` **или** `b > 0`.

```text
n = 0
пока a > 0 или b > 0:
    x = a % 10
    y = b % 10
    если b = 0 или (a > 0 и x > y):
        n = 10*n + x
        a = a // 10
    иначе:
        n = 10*n + y
        b = b // 10
вывести n
```

![Объединение цифр: ввод a,b, накопитель n=0, цикл до исчерпания обоих чисел, выбор доступной большей цифры, приписывание справа.](/assets/digit-merge-right.svg)

| Шаг | a до шага | b до шага | Выбранная цифра | n после шага | a после шага | b после шага |
|---|---:|---:|---:|---:|---:|---:|
| 1 | 13 | 229 | 9 | 9 | 13 | 22 |
| 2 | 13 | 22 | 3 | 93 | 1 | 22 |
| 3 | 1 | 22 | 2 | 932 | 1 | 2 |
| 4 | 1 | 2 | 2 | 9322 | 1 | 0 |
| 5 | 1 | 0 | 1 | 93221 | 0 | 0 |

**Результат:** $93221$.

Условие цикла с «или» позволяет обработать остаток второго числа. Проверка доступности цифры нужна потому, что ноль у исчерпанного числа не должен участвовать в сравнении как настоящая цифра.

:::

:::example Объединение цифр: заполнение разрядов

**Задача.** Объединить те же цифры, но размещать выбранную цифру в очередном разряде результата: сначала единицы, затем десятки, сотни и т. д.

Начальные значения: `n = 0`, `L = 1`. Правило выбора цифры сохраняется; меняется накопление результата.

```text
n = 0
L = 1
пока a > 0 или b > 0:
    x = a % 10
    y = b % 10
    если b = 0 или (a > 0 и x > y):
        n = n + x*L
        a = a // 10
    иначе:
        n = n + y*L
        b = b // 10
    L = 10*L
вывести n
```

![Объединение цифр: цикл с выбором доступной большей цифры, прибавление цифры с весом L и увеличение веса в десять раз.](/assets/digit-merge-place.svg)

| Шаг | Выбранная цифра | L до шага | Действие | n после шага |
|---|---:|---:|---|---:|
| 1 | 9 | 1 | 0 + 9·1 | 9 |
| 2 | 3 | 10 | 9 + 3·10 | 39 |
| 3 | 2 | 100 | 39 + 2·100 | 239 |
| 4 | 2 | 1000 | 239 + 2·1000 | 2239 |
| 5 | 1 | 10000 | 2239 + 1·10000 | 12239 |

**Результат:** $12239$. Выбираемые цифры одинаковы в обеих схемах; итоговый порядок меняется из-за способа накопления результата.

:::

### Проверка числа на палиндром

Проверка строится на переносе последних цифр числа в накопитель `m`. Первая половина остаётся в `n`, вторая постепенно разворачивается в `m`.

Цикл выполняется, пока `n > m`. На каждом шаге:

$$
k=n\bmod10,\qquad m=10m+k,\qquad n=n\mathbin{//}10.
$$

:::example Палиндром: разворот половины цифр

**Задача.** Проверить, читается ли десятичная запись целого неотрицательного числа одинаково слева направо и справа налево. В записи нет ведущих нулей.

```text
ввести n
m = 0
если n != 0 и n % 10 = 0:
    вывести False
иначе:
    пока n > m:
        k = n % 10
        m = 10*m + k
        n = n // 10
    вывести (n = m или n = m // 10)
```

![Проверка палиндрома: исключение ненулевого числа с последним нулём, разворот половины цифр и сравнение половин с учётом средней цифры.](/assets/palindrome-half.svg)

**Трассировка для 1221:**

| Состояние | k | n | m |
|---|---:|---:|---:|
| До цикла | — | 1221 | 0 |
| После первого шага | 1 | 122 | 1 |
| После второго шага | 2 | 12 | 12 |

Условие `n > m` стало ложным; `n = m`, поэтому результат — **True**.

**Трассировка для 123:**

| Состояние | k | n | m |
|---|---:|---:|---:|
| До цикла | — | 123 | 0 |
| После первого шага | 3 | 12 | 3 |
| После второго шага | 2 | 1 | 32 |

Ни `n = m`, ни `n = m // 10` не выполнено; результат — **False**.

При нечётном количестве цифр средняя цифра оказывается в конце `m`: сравнение `n = m // 10` её отбрасывает. Например, для 121 в конце получаются `n = 1`, `m = 12`.

Ненулевое число, заканчивающееся нулём, сразу исключается: его запись без ведущих нулей не может быть палиндромом. Само число 0 проходит проверку.

:::
