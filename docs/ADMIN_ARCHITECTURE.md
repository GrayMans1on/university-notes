Продолжение разработки включает реализацию описанного Worker. Код: service/schedule/worker.mjs; общий валидатор: scripts/schedule-validation.mjs; клиент: assets/schedule-admin.js; Android-мост: ScheduleService (APK 1.1.1). Есть отдельный workflow тестирования и явного развёртывания.

Worker ещё не опубликован: в текущей сессии нет доступа к Cloudflare и ключа установленной GitHub App. Поиск доступного подключения Cloudflare результата не дал. Поэтому assets/schedule-service.json оставлен с пустым URL. Сценарий по коду проверен на тестовом GitHub API, а не на реальном сервере. Порядок включения — service/schedule/README.md. Повторное согласование архитектуры не является техническим блокером; блокер — доступ к аккаунтам и секретам.

После включения URL клиент скрывает ввод GitHub-токена и отправляет событие по коду. Постоянные и разовые правки проверяются тем же валидатором, что сборка сайта. Для целостного снимка трёх файлов создаётся один коммит и выполняется только fast-forward обновление main; конфликт сохраняет черновик. История не удаляется. До включения сохраняется прежний способ работы.

# Сохранение одной кнопкой без токена — требуется согласование сервиса (16 октября 2026)

Запрошено: выбрать пару, задать правку, нажать «Сохранить изменение» без GitHub-токена на устройстве. Статические GitHub Pages и APK не могут сами выдать права записи в GitHub.

Предлагаемый минимальный компонент: один Cloudflare Worker без D1 и другой базы. Приложение передаёт короткий код администратора, тип журнала, событие и исходный SHA. Worker сравнивает код, проверяет схему и исходную пару, получает GitHub App installation token и дописывает только один из двух JSON-журналов. При конфликте SHA отвечает 409; удаления и правки базового расписания запрещены. Историю и откат хранит сам GitHub. Закрытый ключ GitHub App и код проверки хранятся в secrets Worker, не в APK. Постоянного AI API нет.

Пользовательский сценарий: вход по коду один раз на устройстве; затем одна кнопка сохранения. Сетевая политика приложения применяется к запросам. Офлайн остаётся черновик; сохранение у всех подтверждается только после ответа сервиса и публикации Actions. Автоматическая запись без внешней авторизации не имитируется.

Сервис не реализован и не подключён: владелец ранее потребовал отдельного согласия перед серверным компонентом. Для запуска потребуется аккаунт Cloudflare и установка GitHub App с Contents: Read and write только для этого репозитория. До согласования работает прежний способ через собственный GitHub-токен. В интерфейсе уже объединены создание правки и сохранение; загрузка свежего SHA запускается при входе. Токен по-прежнему нужен и хранится только в памяти сеанса.

# Актуальная админка — решение владельца от 14 октября 2026

Владелец отменил требование защищённой серверной авторизации. Используется простое сравнение короткого текстового кода в клиенте. Это переключатель функций устройства. Cloudflare Worker, D1 и отдельный сервер не подключаются.

Код включает две отдельные формы: постоянные изменения с даты и разовые изменения на конкретную дату. Постоянный исходный цикл в `content/schedule.json` не перезаписывается. Компактные JSON-журналы `content/schedule-overrides.json` и `content/schedule-exceptions.json` содержат только изменения. Откат дописывает `revoke`; прежние записи сохраняются. GitHub дополнительно хранит коммиты всех версий.

Для обмена приложение и сайт используют GitHub Contents API. Публичное чтение работает без токена; для записи администратор вводит собственный fine-grained GitHub-токен с доступом только к `GrayMans1on/university-notes` и разрешением `Contents: Read and write`. Токен живёт в памяти текущего сеанса, не сохраняется в localStorage/SharedPreferences, в журнале, исходниках или APK. Короткий код не даёт серверных прав GitHub.

Перед сохранением загружается свежая версия и SHA журнала. При конфликте другой администратор не перезаписывается: черновик сохраняется на устройстве, требуется обновить данные и пересоздать его. Каждая операция создаёт отдельный коммит. После успешной публикации Actions изменения доступны всем; офлайн остаются сохранённые материалы и черновик.

В Android 1.0.3 запросы выполняет нативный мост, который читает только базовое расписание и оба журнала, а записывает только журналы. Он не позволяет удаление файлов, правки учебных материалов или запись в другие репозитории. Постоянные изменения применяются и в виджетах. Установка 1.0.3 поверх подписанной 1.0.2 сохраняет данные: сертификат прежний.

# Защищённое управление расписанием — проект для согласования

Статус: сервер не подключён и не развёрнут. Кнопка ввода кода в Android отключена до согласования архитектуры. Публичный JavaScript не содержит кода администратора, его хеша или GitHub-токена.

Предлагаемый компонент: Cloudflare Worker с D1. Сайт остаётся на GitHub Pages; Android сохраняет встроенную базу, закладки и офлайн-работу. Это отдельный внешний сервис, требующий аккаунта, настройки доступа и согласия владельца до реализации.

1. Ввод кода отправляется по HTTPS на Worker. Проверка выполняется только сервером: стойкий хеш с солью в закрытом хранилище, ограничения попыток, задержка и блокировка перебора. Код достаточно длинный и случайный; короткий PIN не используется.
2. Сервер выдаёт краткоживущую сессию. В браузере применяется HttpOnly Secure cookie с SameSite и защитой CSRF; для Android потребуется отдельный нативный токен с защищённым хранением. Сессии отзываются сервером. CORS разрешает только адрес сайта; все операции дополнительно требуют действующей сессии.
3. Авторизованный администратор выбирает группу, дату, существующую пару и действие: отмена, перенос, замена кабинета/времени или дополнительная пара. Сервер проверяет схему, исходное занятие, права группы и номер ревизии. Клиент не определяет право записи.
4. D1 хранит журнал событий: автор, время, основание, прежняя ревизия и новое событие. Исправление добавляет запись `supersedes`; удаления истории нет. Повторный запрос с тем же идентификатором не создаёт дубликат.
5. Серверная интеграция GitHub App публикует снимок журнала только в `content/schedule-exceptions.json` отдельным коммитом с проверкой текущего SHA. Закрытый ключ остаётся на сервере. Приложению не выдаётся GitHub-токен. У GitHub App доступ только к этому репозиторию; сервер дополнительно ограничивает разрешённый путь.
6. GitHub Actions проверяет данные и публикует сайт и Android-манифест. После публикации клиенты получают только изменённые файлы обычным механизмом SHA-256. Офлайн доступна последняя проверенная версия. Прямая серверная выдача дельт возможна позже, отдельным решением.

Задержка появления правки — время коммита и публикации Actions; форма показывает состояние «сохранено / публикуется / опубликовано / ошибка». Отсутствие интернета не выдаётся за успешное сохранение. Учебные материалы и постоянный двухнедельный цикл через эту админку не редактируются.

Начальный объём — вход, выход, список исключений, создание и исправление исключения, просмотр журнала. Другие административные права не включаются без нового требования.

До согласования поддержан безопасный путь через GitHub: изменения журнала проходят те же проверки сборки. Реальные исключения не придуманы; начальный журнал пуст.
